# V1-07 · Brouillons sans envoi

Vague 1. Dépend de : V1-05. Sections de `SPEC.md` à lire : 3, 6, 8.

## Objectif

Gérer le cycle de vie d'un brouillon de message, sans aucune capacité d'envoi.

## Fichiers à créer ou modifier

- `src/cabinet/services/drafts.py`
- `src/cabinet/web/routes/drafts.py`
- `src/cabinet/web/templates/drafts.html`
- `src/cabinet/web/static/app.js`
- `tests/unit/test_drafts.py`

## Contrat

```python
def create_draft(session, kind, recipients, subject, body, meeting_id=None, capture_id=None) -> Draft: ...
def update_draft(session, draft_id, subject, body, recipients) -> Draft: ...
def set_status(session, draft_id, new_status) -> Draft: ...
def mailto_link(draft: Draft) -> str: ...
class TransitionError(Exception): ...
```

- Transitions permises : `brouillon` vers `valide` ou `rejete`, `valide` vers `envoye_a_la_main`. Toute autre lève `TransitionError`, rendue en 409 par la route.
- La modification n'est possible qu'à l'état `brouillon`.
- La validation écrit `brouillons/AAAA-MM-JJ_<kind>_<id>.md` (objet, destinataires, corps).
- `mailto_link` encode destinataires, objet et corps (accents et retours à la ligne compris). Le lien « Ouvrir dans la messagerie » et le bouton « Copier » n'apparaissent qu'à l'état `valide`.
- `GET /brouillons` liste les brouillons par état. `POST` pour modifier, valider, rejeter, marquer envoyé à la main, puis redirection.
- `app.js` ne contient que la copie dans le presse-papiers.

## Critères d'acceptation

1. Les transitions permises réussissent. `rejete` vers `valide` et `brouillon` vers `envoye_a_la_main` renvoient 409.
2. La validation crée le fichier d'export avec l'objet et le corps.
3. Modifier un brouillon à l'état `valide` renvoie 409.
4. Le lien `mailto:` est absent de la page pour un brouillon non validé.
5. Décoder le lien `mailto:` d'un brouillon contenant accents et retours à la ligne redonne l'objet et le corps d'origine.
6. Aucun fichier de `src/` ne contient `smtplib`, `sendMail` ni `send_message`.
