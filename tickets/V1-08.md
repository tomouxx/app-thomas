# V1-08 · Orchestrateur du pipeline

Vague 1. Dépend de : V1-03, V1-04, V1-05. Sections à lire : `specs/03 §5.3`, `specs/05 §3`, `specs/08 §2.3`. En cas d'écart avec ce ticket, `specs/` fait foi.

## Objectif

Enchaîner les agents dans l'ordre, journaliser chacun et empêcher deux exécutions simultanées.

## Fichiers à créer ou modifier

- `src/cabinet/agents/pipeline.py`
- `src/cabinet/cli.py`
- `src/cabinet/web/routes/dashboard.py`
- `src/cabinet/web/templates/dashboard.html`
- `tests/unit/test_pipeline.py`

## Contrat

```python
class PipelineBusy(Exception): ...

class Pipeline:
    def __init__(self, agents: list[Agent], lock_path: Path): ...
    def run(self, session_factory) -> dict[str, AgentOutcome | str]: ...

def build_pipeline(settings) -> Pipeline: ...
```

- Chaque agent s'exécute dans `record_run`, avec sa propre session. L'échec d'un agent est noté et le suivant s'exécute quand même.
- Le verrou est le fichier `data/pipeline.lock`. S'il existe, `run` lève `PipelineBusy`. Il est retiré à la fin, même après une exception.
- `build_pipeline` assemble pour cette vague : ingestion, agenda. Les vagues suivantes y ajouteront leurs agents dans l'ordre de `specs/05 §3.3`.
- `cabinet run` exécute le pipeline et affiche une ligne par agent. Code de sortie 0 sans erreur, 1 sinon, 2 si le pipeline est occupé.
- `POST /traiter` exécute le pipeline puis redirige vers `/` avec un résumé. Le tableau de bord porte le bouton « Traiter maintenant ».

## Précisions de la spécification

- Le verrou contient le numéro du processus. Le verrou d'un processus mort est repris (`specs/05 §3.2`).
- L'orchestrateur recopie le modèle et les tokens de l'`AgentOutcome` sur la ligne de journal (`specs/05 §2.3`).

## Critères d'acceptation

1. Les agents s'exécutent dans l'ordre de la liste.
2. Un agent qui lève une exception est journalisé à l'état `erreur` et l'agent suivant s'exécute.
3. Une exécution lancée pendant qu'une autre tient le verrou lève `PipelineBusy`.
4. Le verrou est retiré après une exécution normale et après une exécution en erreur.
5. `cabinet run` sort avec 0, 1 ou 2 selon le contrat.
6. `POST /traiter` redirige vers `/` et le résumé apparaît sur la page.
