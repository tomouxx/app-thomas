# V3-03 · Lecture d'une capture d'écran par le modèle

Vague 3. Dépend de : V3-02. Sections à lire : `specs/07 §3` et `§4.1`. En cas d'écart avec ce ticket, `specs/` fait foi.

## Condition

Ticket conditionnel. La condition est levée : le serveur local accepte les images, vérifié le 24.11.2026 (`specs/00 §4.5`). Le ticket est maintenu.

## Objectif

Lire une capture d'écran de l'outil d'imputation quand le serveur local accepte les images.

## Fichiers à créer ou modifier

- `src/cabinet/llm/prompts/__init__.py`
- `src/cabinet/llm/prompts/app_vision.py`
- `src/cabinet/agents/timesheets.py`
- `tests/unit/test_app_vision.py`

## Contrat

```python
class CaptureOut(BaseModel):
    period: str | None
    lines: list[TimesheetLineData]
```

- Le prompt demande de recopier le tableau visible, sans rien déduire ni compléter, et de laisser de côté toute ligne illisible.
- `TimesheetsAgent` traite aussi la nature `app_capture_image` : appel du modèle avec l'image et le schéma `CaptureOut`, création d'une `timesheet_capture` de source `vision`.
- Si le modèle échoue, l'élément passe à `erreur` avec le message « Le serveur local n'a pas pu lire l'image. Dépose la page en HTML ou en texte. »

## Précisions de la spécification

- La phrase de garde d'une image est la constante `IMAGE_GUARD_SENTENCE` de `llm/prompts/__init__.py` (`specs/07 §3`).

## Critères d'acceptation

1. Avec une doublure du modèle, une image donne une capture de source `vision` avec les lignes du jeu de test.
2. L'image est transmise au modèle (la doublure reçoit un chemin d'image).
3. Une `LLMError` passe l'élément à `erreur` avec le message du contrat.
4. Une capture de source `vision` a toujours `verified` à faux à la création.

## Hors périmètre

Reconnaissance de caractères hors du modèle.
