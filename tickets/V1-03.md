## Contrat

```python
class InboxFile(BaseModel):
    path: Path; sha256: str; kind: str; name_date: date | None; size: int

class AgentOutcome(BaseModel):
    processed: int = 0
    errors: int = 0

class FolderInbox:
    def __init__(self, root: Path): ...
    def scan(self) -> list[InboxFile]: ...

class IngestionAgent:
    name = "ingestion"
    def __init__(self, inbox: Inbox): ...
    def run(self, session) -> AgentOutcome: ...
```

- La nature suit le tableau de la section 5.2 de `SPEC.md`. L'extension est comparée sans tenir compte de la casse.
- `name_date` vient d'un nom qui commence par `AAAA-MM-JJ_`. Sinon il vaut `None`.
- `scan` ignore les sous-dossiers, les fichiers cachés, les fichiers dont le nom commence par `~$` et les fichiers modifiés depuis moins de 5 secondes.
- L'agent crée un `inbox_item` par fichier dont l'empreinte est nouvelle. État de départ : `consentement_requis` pour l'audio, `pret` pour les captures `app_`, `ignore` pour la nature `inconnu`, `a_rattacher` pour le reste.
- `agents/base.py` définit le protocole `Agent` et `AgentOutcome`.

## Critères d'acceptation

1. Chaque ligne du tableau de la section 5.2 est couverte par un cas de test, extension en majuscules comprise.
2. `2026-11-23_point-hebdo.vtt` donne `name_date` au 23.11.2026. `notes.md` donne `None`.
3. Un fichier caché, un fichier `~$brouillon.docx` et un fichier modifié à l'instant sont ignorés.
4. Deux exécutions de suite ne créent pas de doublon.
5. Un fichier audio arrive à l'état `consentement_requis`, une capture `app_nov.html` à l'état `pret`, un `.zip` à l'état `ignore`.
6. `run` renvoie le nombre de nouveaux éléments dans `processed`.
