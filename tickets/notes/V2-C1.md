# Notes V2-C1

## Choix : fichier hors liste — `src/cabinet/db/models.py`

Le ticket ne liste pas `src/cabinet/db/models.py`, mais le critère 4 du contrat
(`test_c4_no_french_identifier_in_src`) l'exigeait.

Question : les membres `NOUVEAU` (specs/02 §2.2.1) et `TEXTE` (specs/02 §2.11)
sont des noms fixés par la spécification et conservés par le contrat du ticket,
or l'analyseur du test n'exempte les membres d'énumération que lorsque la classe
de base est un nom simple se terminant par « Enum » (`StrEnum`). Avec la base
`enum.StrEnum` (accès à un attribut), ces deux membres étaient signalés.

Choix : `from enum import StrEnum` et bases en `StrEnum` nu (10 classes de base
et l'annotation de `_enum_type`). Raisons : c'est le changement minimal qui rend
le critère 4 satisfaisable sans toucher aux noms imposés par la spécification ;
aucun comportement ne change (même classe, mêmes valeurs stockées).

## Choix : champs de formulaire des routes synchrones

`Annotated[str, Form("x")]` est refusé par FastAPI au chargement de
l'application : l'argument positionnel de `Form` est la valeur par défaut, et
une valeur par défaut ne peut pas être donnée dans `Annotated`.

Choix : `Form()` quand le nom du paramètre est celui du champ
(`meeting_id`, `subject`, `body`, `recipients`), et `Form(alias="titre")`,
`Form(alias="date")`, `Form(alias="consentement")` pour les champs dont le nom
français est fixé par les contrats V1-06/V1-07 (les tests de contrat POSTent
avec ces noms et lisent `name="..."` dans le HTML). Raisons : les noms de
champs du formulaire restent ceux des contrats ; seuls les noms de paramètres
des routes sont en anglais, comme l'exige le critère 4.

## Choix : test de la seconde course du verrou (précision 10)

La course « un autre processus recrée le verrou entre notre suppression du
verrou périmé et notre création atomique » (specs/05 §3.2) n'est pas
reproductible de façon fiable avec deux vrais processus dans un test unitaire.

Choix : `test_stale_lock_recreated_by_other_process_raises_busy` simule
l'intrus en remplaçant `Pipeline._create_lock` sur l'instance (monkeypatch) :
au second appel, après la suppression du verrou périmé, le fichier est recréé
avec notre propre numéro de processus avant l'appel à la création atomique
d'origine, qui lève alors `FileExistsError`. Raisons : la simulation passe par
le même point d'entrée que le vrai processus concurrent (la création atomique),
et le test vérifie les deux conséquences attendues — `PipelineBusy` levée et
verrou laissé en place, car le `finally` de `run` ne s'exécute pas quand
l'acquisition échoue.

## Choix : renommages dans `tests/unit/` au-delà de la liste du contrat

Le ticket demande de renommer « tous les identifiants qui ne sont pas des noms
de fonctions de test » en anglais dans `tests/unit/` ; la liste du contrat est
un minimum, pas une limite.

Choix : dans `test_pipeline.py` et `test_sante.py`, en plus des identifiants
signalés, j'ai renommé les autres noms français du même fichier : `AgentFactice`
→ `FakeAgent`, `_lancer` → `_run`, `verrou` → `lock`, `_pid_mort` → `_dead_pid`,
`passages` → `order`, `erreur` → `error`, `processus` → `process`, `nom` →
`name`, `chemin` → `lock_path`, `resultat` → `outcomes` (dictionnaire du
pipeline) ou `result` (résultat Typer, convention de `test_llm_client.py`),
`faux_pipeline` → `fake_pipeline`, `reponse` → `response`. Raisons : laisser des
noms français à côté de noms anglais dans le même fichier aurait rendu la
convention incohérente ; les fonctions `test_*` gardent leurs noms français,
comme le permet le contrat.

## Choix : fichier illisible du dossier d'entrée (question Q2)

Question : un fichier dont l'empreinte ne peut pas être calculée (erreur
d'accès) doit-il faire échouer le balayage ?

Choix : `_to_inbox_file` renvoie `None` sur `OSError` et `scan` passe à
l'entrée suivante ; le fichier reste dans le dossier sans état d'erreur et est
repris au passage suivant. Raisons : specs/05 §5.2 ne définit pas d'état
d'erreur pour le balayage ; faire échouer tout le pipeline à cause d'un fichier
temporairement illisible (copie en cours) serait plus nuisible que de le
retrouver au passage suivant.

## Choix : `cabinet run` avec une configuration illisible (précision 8)

Choix : la commande `run` attrape `ConfigError`, affiche le message sur la
sortie d'erreur et sort avec le code 1 via `typer.Exit(code=1)` — pas de
traceback. Raisons : le message de `ConfigError` est déjà lisible et en français
(précision 7) ; le code de sortie 1 distingue une panne de configuration d'un
échec du pipeline, qui sort aussi avec 1 mais après avoir journalisé.

## Choix : libellés des champs sans étiquette (précision 9)

Choix : dans `inbox.html`, les champs « Titre de la réunion » et « Date de la
réunion » reçoivent un `<label for>` avec des identifiants `titre-{{ item.id }}`
et `date-{{ item.id }}` (un identifiant par élément, car le formulaire est
répété dans la boucle) ; dans `drafts.html`, l'aire de lecture du message
reçoit `<label for="message-{{ draft.id }}">Message à copier</label>`. La case
de consentement était déjà enveloppée dans un `<label>`. Raisons : le contrat
exige un libellé associé à chaque champ ; l'identifiant par élément évite les
doublons quand plusieurs éléments affichent leur formulaire.
