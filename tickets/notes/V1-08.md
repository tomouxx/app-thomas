# Notes de l'exécutant — V1-08

## Blocage : `make check` avec les contrats du ticket activés

Pour exécuter directement les tests de contrat de V1-08, il faut les activer
(`CABINET_TICKET=V1-08` ou `CABINET_CONTRATS=tous`, voir
`tests/contrats/conftest.py`) : tant que le ticket n'est pas « fait » dans
`tickets/ETAT.md`, `pytest_ignore_collect` les ignore. La commande
`CABINET_TICKET=V1-08 make check` a été refusée par la chaîne de permissions ;
le refus est définitif (`docs/EXECUTANT.md`, règle 31) et je ne l'ai ni
relancée ni contournée.

Conséquences :

- `make check` tel quel passe (ruff propre, 645 tests) : il vérifie tout le
  reste du dépôt, dont les contrats actifs (V1-C1 sur `src/cabinet`, etc.).
- Les tests de contrat de V1-08 (27 fonctions, 30 tests après paramétrage)
  n'ont pas tourné dans ma session. Ils
  tourneront au relancement de `make check` par le script de boucle, qui
  active le ticket en cours ; c'est ce relancement qui fait foi.
- En attendant, j'ai relu `tests/contrats/test_v1_08_pipeline.py` test par
  test et confronté chaque assertion à l'implémentation (ordre d'exécution,
  valeurs `AgentOutcome`/chaîne du résultat, journal par agent, verrou tenu /
  périmé / retiré, codes de sortie 0/1/2 de `cabinet run`, redirections 303
  et messages exacts de `POST /traiter`, bouton du tableau de bord, copie des
  tokens seulement si > 0). Aucun écart constaté.
