# Notes de l'exécutant — V0-03

## Fichiers hors liste du ticket : `__init__.py` et `tests/unit/conftest.py`

1. `src/cabinet/db/__init__.py`, `src/cabinet/agents/__init__.py` et
   `src/cabinet/web/routes/__init__.py` : le ticket liste les modules des trois
   nouveaux dossiers mais pas leurs `__init__.py`. La spécification l'exige :
   « Un dossier de `src/cabinet/` devient un paquet (fichier `__init__.py`
   vide) à la tâche qui y crée son premier module » (`specs/01 §2`). Sans eux,
   les dossiers ne sont pas des paquets pour `[tool.setuptools.packages.find]`.
   J'ai créé les trois fichiers vides, changement minimal, comme pour V0-01 et
   V0-02.

2. `tests/unit/conftest.py` : depuis ce ticket, `create_app()` appelle
   `init_db()`, qui crée la base sous `CABINET_HOME` (repli `~/Cabinet`).
   Les tests unitaires existants (`tests/unit/test_sante.py`) appellent
   `create_app()` sans fixer `CABINET_HOME` : sans isolation, ils créeraient
   la base dans le vrai répertoire `~/Cabinet`, ce que la règle 3 de
   `CLAUDE.md` interdit. J'ai ajouté un fixture autouse qui pointe
   `CABINET_HOME` sur un répertoire temporaire pour tous les tests unitaires,
   à l'image du fixture `environnement_isole` des tests de contrat.

## Détail d'implémentation : `functools.cache` au lieu de `lru_cache(maxsize=None)`

La spécification (`specs/05 §2.1`) parle d'un moteur « mis en cache sur le
chemin via `functools.lru_cache` ». Le dépôt impose les règles ruff de
`specs/00 §4.8`, dont UP033 qui exige `functools.cache` plutôt que
`lru_cache(maxsize=None)`. Les deux sont le même mécanisme (`cache` est
l'alias de `lru_cache(maxsize=None)`), le comportement demandé — un moteur par
chemin, résolu à chaque appel de `get_engine()` — est respecté.
