# Notes V1-C1

## Choix : langue des noms dans les deux nouveaux tests de `tests/unit/test_journal.py`

Le ticket limite la précision 2 (identifiants en anglais) à `src/`, et dit que les
tests de `tests/unit/` « suivent les nouveaux noms quand ils les citent ». Les deux
nouveaux tests ne citent aucun nom renommé (ils n'utilisent que `record_run`,
`get_session`, `AgentRun`, qui ne changent pas).

Question : faut-il écrire les nouveaux tests avec des identifiants anglais, comme
l'exige `specs/01 §5` pour tout le code, ou suivre la convention du fichier existant
(noms de tests et variables locales en français, acceptés à la revue de la vague 0) ?

Choix : suivre la convention du fichier (noms de tests et variables locales en
français, docstrings en français). Raisons : le ticket borne explicitement les
renommages à `src/` ; le test de contrat ne vérifie la langue que sur `src/` ;
les fichiers de tests de la vague 0, déjà revus et fusionnés, utilisent cette
convention. Renommer les variables des tests existants aurait été un refactor hors
périmètre du ticket.
